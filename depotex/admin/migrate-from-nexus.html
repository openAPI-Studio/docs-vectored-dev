Move from Nexus Repository

Move a Sonatype Nexus Repository 3 installation to Depotex with the nx2dx tool: assess, plan, create repositories, copy content, verify, and keep large repositories in Nexus behind a Depotex cache

1. Overview

nx2dx moves a Sonatype Nexus Repository 3 installation to Depotex: it creates the spaces, upstreams and hosted, proxy and group repositories with their settings, then copies the content of hosted repositories and checks the copy. Each repository can instead be kept in Nexus behind a Depotex cache, which suits large repositories or archives you don't want to copy, and lets teams switch to Depotex before any content has moved.

Source code: https://github.com/akshaykg/Nexus-to-Depotex (akshaykg/Nexus-to-Depotex on GitHub). Ask support for a copy of the tool if you can't open the repository.

  • It reads Nexus only through its REST API and its repository addresses, and writes to Depotex only through Depotex's public API with one API token. No server changes and no plugin are needed on either side.
  • It never changes or deletes anything in Nexus, and never deletes anything in Depotex.
  • Every step can be run again: it reads before it writes, creates what is missing and copies only what is new.
  • It is one Python file with no dependencies, so it runs on locked-down hosts.

3. Get the tool

Clone https://github.com/akshaykg/Nexus-to-Depotex and build the single-file version, which you can copy to any machine with Python:

git clone https://github.com/akshaykg/Nexus-to-Depotex.git
cd Nexus-to-Depotex
scripts/build-pyz.sh                 # writes dist/nx2dx.pyz
python3 dist/nx2dx.pyz --help

# or run it from the checkout, or install it as a command
python3 -m nx2dx --help
pip install . && nx2dx --help

The examples below write nx2dx; use python3 nx2dx.pyz if you didn't install it. nx2dx --version shows the version.

4. How a migration goes

  1. Assess — nx2dx assess reads Nexus and writes a report: every repository with its size, last download, a suggested mode and what needs attention. Nothing changes.
  2. Plan — nx2dx plan decides the space of each repository and what happens to it, and writes plan.json, which you can edit.
  3. Apply — nx2dx apply creates the spaces, upstreams, repositories and groups in Depotex. Try it with --dry-run first.
  4. Warm the cache (repositories kept in Nexus) — nx2dx warm fetches the files people used recently through Depotex, so they're cached before builds switch.
  5. Copy — nx2dx copy moves the content of hosted repositories into Depotex while Nexus stays in use.
  6. Verify — nx2dx verify checks every copied file in Depotex against Nexus.
  7. Freeze and catch up — Make Nexus read-only, run copy once more for the last changes, and verify again.
  8. Switch clients — Point builds and developers at Depotex with API tokens. Keep Nexus read-only for a while, then retire it.

By default every file goes into the folder nx2dx-out/ of the current directory. Run every step from the same directory, or pass the same --plan to each.

5. Choose what happens to each repository

Defaults are copy for hosted, recreate for proxies and groups. --large-mode picks another mode for big hosted repositories, and --mode sets one repository or a pattern of names.

6. Step 1: Assess

export NX2DX_NEXUS_PASSWORD=…        # Nexus password of --nexus-user
export NX2DX_DEPOTEX_TOKEN=…         # only for --depotex
nx2dx assess --nexus https://nexus.example.com --nexus-user admin --depotex https://depotex.example.com

It writes nx2dx-out/inventory.json (what plan reads) and nx2dx-out/report.md, which lists every repository with its asset count, size, last download, the suggested mode, and what needs attention:

  • names that change in Depotex (upper case, or a format name such as npm, see Names);
  • formats Depotex doesn't serve;
  • Docker repositories Depotex can't proxy (no connector port and not served under /repository/<name>/v2/);
  • YUM repositories with a repodata depth above 0, of which a proxy covers one folder;
  • remotes with credentials (Nexus never returns stored passwords), routing rules that need translating by hand, and offline repositories.

With --depotex the report also shows the target's licence tier. Nexus lists assets ten at a time, so counting a large repository takes long: counting stops at --count-limit assets (the report shows 20000+), and --no-count skips it.

7. Step 2: Plan

nx2dx plan --space-strategy single:nexus \
           --hosted-mode copy \
           --large-mode proxy --large-bytes 50G \
           --upstream-user depotex-reader

Depotex keeps repositories in spaces, and there is no default: you choose where repositories go with --space-strategy (asked for when you run the command at a terminal).

--space-strategyResult
single:<key>Every repository in one space. Client addresses change least: /repository/<repo>/ becomes /repository/<key>/<repo>/
prefixA space per name prefix, up to the first -, _ or .: team-maven goes to space team
formatA space per format: maven, npm…
map:<file.json>A JSON file of {"<repository name or pattern>": "<space key>"}. The first match wins; repositories that match nothing are skipped

Group members must be in the group's space: a member that goes to another space is left out of the group, and the plan says so. With prefix, a group such as maven-public whose members are named releases or central loses them; use single or a map file instead.

OptionDefaultMeaning
--hosted-modecopycopy, proxy, bridge or skip for hosted repositories
--proxy-moderecreaterecreate, proxy (through Nexus) or skip for Nexus proxies
--group-moderecreaterecreate, proxy (a proxy of the Nexus group) or skip for Nexus groups
--large-mode with --large-bytes SIZE and/or --large-assets NAnother mode for big hosted repositories, for example --large-mode proxy --large-bytes 50G. Sizes take K, M, G and T
--mode 'NAME=MODE'Mode for one repository or a pattern such as 'archive-*=proxy'; repeatable, the first match wins
--nexus-upstream-url URLthe assess addressNexus's address as Depotex reaches it (an internal name)
--upstream-user NAMEnoneNexus account Depotex signs in with when it proxies Nexus; a read-only one is enough
--visibilityinternalVisibility of new spaces: private, internal or public
--artifact-max-age MIN60Minutes before a cached Nexus file that may still be overwritten is checked again
--metadata-max-age MIN5Minutes before cached Nexus metadata (Maven metadata, npm documents, indexes) is checked again

--inventory FILE, -o FILEnx2dx-out/inventory.json, nx2dx-out/plan.jsonInput and output. The output's folder must exist

When Depotex proxies Nexus (proxy and bridge modes), files are cached for good when the Nexus repository is publish-once (write policy Disable redeploy or Read-only), and otherwise re-checked after --artifact-max-age. Metadata and "not found" are re-checked after a few minutes, so versions still published to Nexus show up quickly.

plan prints a summary with notes on everything that needs a person, and writes nx2dx-out/plan.json. You may edit it before applying: a repository's mode, space or name, or an upstream's key, url or credentials. apply and copy check an edited plan and list its problems before doing anything.

8. Step 3: Apply

export NX2DX_DEPOTEX_TOKEN=…
export NX2DX_UPSTREAM_PASSWORD=…     # with --upstream-user
nx2dx apply --depotex https://depotex.example.com --dry-run     # what would change
nx2dx apply --depotex https://depotex.example.com

It creates the spaces (or adds formats to existing ones), the upstreams, each space's list of allowed upstreams, the repositories, then the groups (a group that contains another group after it), and sets each repository's settings. Running it again changes only what differs from the plan.

  • A repository or upstream that already exists in Depotex with another format, type or address is reported as an error and left alone: give it another name or key in the plan.
  • Credentials of a Nexus proxy's remote come from NX2DX_SECRET_<REPOSITORY>. Without it the upstream is created without credentials (reported as a warning); add them under Upstreams in the sidebar (Upstreams).
  • --only NAME,NAME limits the run to some Nexus repositories (create a group's members before the group).
  • Results are also written to nx2dx-out/apply-results.json (--results). The exit code is 1 when anything failed.

9. Step 4: Warm the cache

For repositories kept in Nexus (proxy and bridge modes), fetch the files Nexus says were downloaded recently through Depotex, so the first builds after the switch don't all wait on Nexus, and those files keep working if Nexus is later switched off:

nx2dx warm --nexus https://nexus.example.com --nexus-user admin --depotex https://depotex.example.com --since-days 90 -j 8
OptionDefaultMeaning
--since-days N90Files Nexus says were downloaded in the last N days
--allEvery file
-j N8Parallel fetches
--limit Nno limitAt most N files per repository
--only NAME,NAMESome Nexus repositories only

Warm-up works for Maven, raw, npm, Helm, APT, YUM, conda and RubyGems, where a file's path in Nexus is the path a client asks Depotex for. Indexes and checksum files are skipped (Depotex refreshes them itself). Other formats fill their cache as clients ask. Files Nexus has never seen downloaded are only fetched with --all.

10. Step 5: Copy content

nx2dx copy --nexus https://nexus.example.com --nexus-user admin --depotex https://depotex.example.com --dry-run     # how many files, how many bytes
nx2dx copy --nexus https://nexus.example.com --nexus-user admin --depotex https://depotex.example.com -j 4

It moves every file of the copy-mode repositories into their Depotex hosted repositories. --bridge also moves the Nexus content of bridge-mode repositories into their -local repository, after which the group no longer needs Nexus. Each file is streamed from Nexus to Depotex, and Depotex checks the checksum Nexus reports.

FormatHow it is copied
Maven, rawTo the same path, so every file name stays (timestamped snapshots, signatures, classifiers). Checksum files are left out because Depotex computes them; a version's POM goes after its other files and maven-metadata.xml after everything
npm, PyPI, NuGet, Helm, APT, YUM, RubyGemsAs the format's own client publishes, in the order Nexus received them. npm dist-tags and deprecations are set as Nexus has them; APT packages go to the Nexus repository's distribution (component main); YUM packages keep their folder and the repository gets Nexus's repodata depth
conda, Cargo, ComposerThe same way, but not yet tried against a Nexus that hosts them: check the result with verify and the format's client
DockerOver the registry API, with no other tool: each tag's manifest (a multi-platform image with every platform), each layer Depotex doesn't have yet, then the tag, checking that Depotex has the same digest as Nexus
Conan, Git LFS, Hugging Face, Terraform, GoNot copied: the repository is created empty. Move Conan and RubyGems packages with their own clients as those pages show; Nexus has no hosted Go

What was copied is recorded in copy-state.db next to the plan (--state for another file). A second run copies only what is new or changed in Nexus, so a typical sequence is a full copy while Nexus is still in use, then Nexus made read-only, then copy once more, or copy --since 2026-12-01 for files Nexus received since that day.

Packages Depotex refuses (invalid metadata, upload rules, quotas) are listed with the reason, and packages a quarantine rule or content check holds on arrival are counted. The exit code is 1 when a file failed.

11. Get Depotex ready for a large copy

  • Rate limits. Give the migration token an override under Settings → Security → Rate limits (Rate limits), or the copy is throttled. Enterprise allows an exempt override.
  • Quarantine and upload rules. Copied versions are new to Depotex: their publish date is the day of the copy. A quarantine age rule or cooldown on hosted repositories would hold every copied version; pause it for the copy or exclude these repositories.
  • Size limits. Check the artifact size limit (Settings → Repositories) against the largest file in the report, and any request body limit in a reverse proxy in front of Depotex. Pointing --depotex at a Depotex server directly avoids the reverse proxy.
  • Read-only and offline repositories. See Known issues: make them writable and online in Depotex for the copy.

12. Step 6: Verify

nx2dx verify --nexus https://nexus.example.com --nexus-user admin --depotex https://depotex.example.com

It checks every file copy takes from Nexus: recorded as copied, present in Depotex, and with the same content (SHA-256, or SHA-1 where Nexus has no SHA-256; for Docker, the manifest digest under each tag). Problems go to nx2dx-out/verify-problems.csv with Depotex's reason (not copied, 404, 403 quarantined: …, a different checksum). Maven metadata that Depotex generates is only checked for presence. The exit code is 1 when there is a problem.

Checking copied content in Depotex against Nexus
  Raw-Files → nexus/raw-files: 3 match, 0 problems
  docker-hosted → nexus/docker-hosted: 1 match, 0 problems
  maven-releases → nexus/maven-releases: 2 match, 0 problems
  npm → nexus/npm-repo: 3 match, 0 problems
  pypi-internal → nexus/pypi-internal: 1 match, 0 problems

13. Step 7: Switch clients

  • Addresses. Clients use https://depotex.example.com/repository/<space>/<repository>/; for a bridge, the group's address. A renamed repository uses its new name (the plan lists them).
  • Docker image names change: nexus.example.com:8082/team/app:1.0 becomes depotex.example.com/<space>/<repository>/team/app:1.0.
  • Credentials. Package clients sign in to Depotex with API tokens, sent as the password in Basic authentication, not with account passwords. Every CI job and developer configuration needs a new token, so set up sign-in (directories, single sign-on) first and let people make their own.
  • APT hosts must trust Depotex's signing key instead of Nexus's (APT).
  • Keep Nexus read-only for as long as you might need to look something up, then retire it. Repositories in proxy or bridge mode need Nexus until their content is copied (copy, or copy --bridge).

14. Examples

A small installation, everything copied, into one space:

nx2dx assess --nexus https://nexus.example.com --nexus-user admin
nx2dx plan --space-strategy single:nexus
nx2dx apply --depotex https://depotex.example.com
nx2dx copy --nexus https://nexus.example.com --nexus-user admin --depotex https://depotex.example.com -j 4
nx2dx verify --nexus https://nexus.example.com --nexus-user admin --depotex https://depotex.example.com

Large repositories kept in Nexus. Every hosted repository over 50 GB stays in Nexus behind a Depotex cache, warmed with the last 90 days' downloads; the rest is copied:

nx2dx plan --space-strategy single:nexus --large-mode proxy --large-bytes 50G \
           --upstream-user depotex-reader
NX2DX_UPSTREAM_PASSWORD=… nx2dx apply --depotex https://depotex.example.com
nx2dx warm --nexus https://nexus.example.com --nexus-user admin --depotex https://depotex.example.com --since-days 90
nx2dx copy --nexus https://nexus.example.com --nexus-user admin --depotex https://depotex.example.com

Switch first, copy later (bridge). Teams move to Depotex at once; new publishes land in Depotex while existing packages come from Nexus, which can be read-only from the first day. The content is copied afterwards:

nx2dx plan --space-strategy single:nexus --hosted-mode bridge --upstream-user depotex-reader
NX2DX_UPSTREAM_PASSWORD=… nx2dx apply --depotex https://depotex.example.com
nx2dx warm --nexus https://nexus.example.com --nexus-user admin --depotex https://depotex.example.com
# later, at your own pace
nx2dx copy --nexus https://nexus.example.com --nexus-user admin --depotex https://depotex.example.com --bridge
nx2dx verify --nexus https://nexus.example.com --nexus-user admin --depotex https://depotex.example.com --bridge

A space per team from a map file, with one archive kept in Nexus:

# spaces.json
{"payments-*": "payments", "search-*": "search", "*": "shared"}

nx2dx plan --space-strategy map:spaces.json --mode 'legacy-archive=proxy' --upstream-user depotex-reader

Freeze and catch up before switching clients:

# make the Nexus repositories read-only, then
nx2dx copy --nexus https://nexus.example.com --nexus-user admin --depotex https://depotex.example.com
nx2dx verify --nexus https://nexus.example.com --nexus-user admin --depotex https://depotex.example.com

16. Names and addresses

  • Depotex repository names are lower case, 2 to 64 characters of a-z 0-9 . _ -, and can't be a format name (maven, npm, docker…). Maven-Releases becomes maven-releases; a repository named npm becomes npm-repo; two names that end up equal get -2, -3.
  • Space and upstream keys are lower case letters, digits and single hyphens, up to 40 characters.
  • Proxies of the same remote with the same account share one upstream. Proxies of known public registries use the preset's key (maven-central, npmjs, pypi, docker-hub…); when Depotex already has an upstream of that key at another address, apply reports it: change the key in the plan.
  • Nexus's PyPI remotes are given as the site (https://pypi.org); the Depotex upstream gets the Simple API address (…/simple).

17. What isn't migrated

NexusWhat to do in Depotex
Users, roles, privileges, content selectors, LDAP and SAML role mappingsNot migrated yet. Connect Depotex to the same directory or single sign-on and give groups space and repository roles (How access fits together). Local users' passwords can't be moved.
Anonymous accessTurn it on under Settings → Security → Anonymous access and put the repositories anonymous users need in a public space.
Cleanup policiesRecreate them per space (Repository settings).
Blob stores and their quotasDepotex has one storage backend; use space quotas.
Routing rules on proxy repositoriesDepotex applies them only as group member routing, which the tool sets on recreated groups. Rules with expressions other than a path prefix or a leading .* are listed in the plan for you to translate.
Publish dates, uploaders and download historyCopied versions get the copy's date and the migration token as uploader. Quarantine ages, cooldowns and "not downloaded for N days" cleanup count from the copy.
Content of Nexus proxy repositories (their caches)Not copied: a recreated proxy fills itself again from its remote.
Formats Depotex doesn't serve (R, p2, Bower, CocoaPods, Go hosted…)Skipped. Keep Nexus for them, or move their files into a raw repository yourself.
Conan, Git LFS, Hugging Face and Terraform contentThe repository is created empty; move the content with the format's client.
Tasks, webhooks, capabilities, email and HTTP proxy settings, SSL certificatesConfigure Depotex's own: scheduler, automation, email, repository settings.
Client configuration and the old hostnameUpdate settings.xml, .npmrc, pip.conf, NuGet sources, Docker image names and so on yourself. A rewrite of the old hostname to Depotex's addresses isn't generated yet.

Docker repositories reached only through a Nexus Pro subdomain connector can be proxied, but not copied: the copy reads the registry under /repository/<name>/v2/ or on the connector port. Images with a schema 1 manifest (Docker 1.9 and older) aren't copied. Layers with foreign URLs are left to their own addresses.

18. Known issues

Problems in the current version of the tool, with what to do until they are fixed:

IssueWorkaround
Read-only and offline Nexus repositories can't be copied. A hosted repository Nexus has as Read-only (write policy Deny) or offline is created the same way in Depotex, which then refuses every copied file (405 repository_read_only, 503 repository_offline; offline repositories are retried before failing).After apply, set the repository to Allow and online in Depotex (Repository settings), run copy and verify, then run apply again to put Nexus's settings back.
warm stops at a file name with a space (or #, ?, %) in a proxied raw or Maven repository, with a Python error, and the repositories after it aren't warmed. A network error or time-out during warm stops the run the same way.Run warm with --only for the other repositories; those files are cached the first time a client asks for them.
npm versions already in Depotex count as failed. When copy runs without its earlier copy-state.db (another machine, a lost or new --state file), or retries a version that reached Depotex before a time-out, Depotex answers version_exists and the version is reported as failed.Keep copy-state.db with the plan and run every copy from the same place. Check reported versions with npm view against Depotex; they are there if the checksum matches.
Versions already in a publish-once Depotex repository show as problems in verify (PyPI, NuGet, Helm and the other formats copied as their clients publish): in the same situation as above they are counted as "already in Depotex" without comparing the file, and verify lists them as copy recorded no Depotex path (exists).Same as above. Download such a version from Depotex and compare its SHA-256 with Nexus's if you need certainty.
With --large-bytes alone, a repository whose count stopped at the limit isn't treated as large, although the report suggests proxy or bridge for it. It is planned as copy.Add --large-assets (for example --large-assets 20000, the counting limit), name it with --mode, or count it fully with assess --count-limit 0.
Credentials added later aren't picked up. An upstream created without credentials (no NX2DX_SECRET_… or NX2DX_UPSTREAM_PASSWORD at the first apply) stays without them when apply runs again: an existing upstream is never changed.Add the credentials under Upstreams in the sidebar (Edit on the upstream).
Routing changes in an edited plan aren't applied to an existing group when its members stay the same, and apply --dry-run doesn't show a changed write member.Change the group's member routing in Depotex (Repository groups).
A missing output folder stops plan and apply with a Python error: plan -o into a folder that doesn't exist, or apply from a directory without nx2dx-out/ (it writes nx2dx-out/apply-results.json there after doing the work).Create the folder, or pass --results to a path that exists. The report's suggested plan command uses paths without nx2dx-out/; run it from inside that folder or add the folder to both paths.
Rate limits. A file refused with 429 or 5xx is tried 3 more times within about 7 seconds, without waiting for the time Depotex asks for.Give the migration token a rate-limit override before a large copy, and lower -j.
Changing a repository's target after a copy. The copy state is kept per Nexus repository and path, so after you change a repository's space or name in the plan, copy thinks its files are done.Use a new state file (--state) for that repository with --only.
Time zones. --since and warm --since-days compare with the dates Nexus reports as text; a Nexus that reports times in another offset than UTC can include or leave out files near the boundary.Give --since a day earlier than you need; copying a file twice does no harm.
